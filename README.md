## Start with the public files

Clone the [versioned collection](https://github.com/research-artifact-archive/seams2027/tree/normalized-eleven-evidence-20261021-v1), which includes all six scientific evidence ZIPs in `archives/` and the separate document snapshot in `documents/`. The following integrity command checks the three historical archives. The fourth archive has its own inspection and replay commands in the [Lift causal extension](LIFT_CAUSAL_EXTENSION.md); the fifth has separate integrity and native-regeneration instructions in the [native addendum](NATIVE_REGENERATION.md); the sixth has its own source binding and saved-input check in [normalized eleven](NORMALIZED_ELEVEN.md). Python 3.10 or newer and its standard library are sufficient for this first check:

```sh
git clone --branch normalized-eleven-evidence-20261021-v1 --depth 1 \
  https://github.com/research-artifact-archive/seams2027.git
cd seams2027
python3 -I -S -B tools/verify_public.py --archive-dir archives
```

Expected output: `PASS_PUBLIC_ARCHIVE_INTEGRITY_ONLY`. This checks the independently published archive hashes, ZIP member names, sizes, and CRCs. It executes no model or scientific checker.

To also extract the files into a new directory:

```sh
python3 -I -S -B tools/verify_public.py \
  --archive-dir archives --extract-to ../evidence-inspection
```

The destination must not already exist. Allow approximately 340 MB for extraction plus a 1 GiB free-space reserve. The archives retain their historical directory prefixes.

## Restore external source files when needed

The original three public ZIPs omit 97 copies of third-party source text whose redistribution terms are not established here: published specification listings and their diffs, selected upstream Java/C sources, and one literature-text bundle. All retained archive members are byte-identical to their counterparts in the three earlier anonymous evidence archives named in `RELEASE_MANIFEST.json`. Earlier metadata anonymization and serialization can give these copies different hashes from their original execution files; the inner manifests and original/copy or receipt ledgers distinguish those identities. Mathematical outputs, controllers, models, and checker implementations remain in the public downloads.

These omissions do not prevent reading the saved results. They do mean the original closed-package metadata check is not ready immediately after extraction. The source-fetch helpers retrieve the omitted material directly from its original distributors and verify every restored byte against the historical hash. The sixth archive omits eleven additional paper-derived specification copies and has a separate source-only restoration manifest inside that archive. Its helper verifies exact listing and reconstructed bytes; whole-HTML historical hash equality is reported without being required. No fresh source retrieval was part of its saved-input qualification.

First restore the published specification listings. This uses only the Python standard library:

```sh
python3 -I -S -B tools/fetch_paper_sources.py \
  --output-root ../evidence-inspection
```

Then restore the upstream code excerpts and literature text. The exact historical PDF-to-text conversion requires `pypdf==6.10.0`; install it in a separate environment:

```sh
python3 -m venv ../source-fetch-env
../source-fetch-env/bin/python -m pip install pypdf==6.10.0
../source-fetch-env/bin/python tools/fetch_external_sources.py \
  --cache ../source-fetch-cache --output-root ../evidence-inspection
```

Finally check all historical member bytes, including the restored files:

```sh
python3 -I -S -B tools/check_restored_tree.py ../evidence-inspection
```

Expected output: `PASS_HISTORICAL_TREE_BYTES_RESTORED_ONLY`. This verifies the complete file trees of those earlier anonymous evidence archives; it does not reproduce the original ZIP container bytes or rerun a scientific computation. Downloads stay in the reader's local cache and retain their original publishers' terms. Any source-byte mismatch stops restoration. See [source retrieval details](tools/PAPER_SOURCE_RETRIEVAL.txt) and [third-party scope](THIRD_PARTY_NOTICES.md).
